# Rust native host migration

The remaining-macOS candidate implements file search with a bounded literal `mdfind -0` query, identity-bound window layouts/restore/screens, process sorting/force quit, and a separate six-tab native System Monitor. The Monitor samples on a bounded worker only while visible and active, every two seconds, with at most 60 samples; CLI `monitor` keeps a separate counter baseline. Settings, Open Configuration, Reload Configuration and Monitor use the existing owners; the coordinator composes their defaults with Dashboard and OS search defaults. `run MENU_ID --foreground ORIGINAL_JSON` carries the exact original identity returned by menu search. Ephemeral file/process/menu identities and content are not persisted as usage or ranking.

`cargo test --features test-tools --test remaining_macos_process --locked` exercises real control sockets, hidden AppKit, an actual rebuilt CLI and complete owned SDK substitutes. Long snapshot paths require a short owned `RUYCAST_NATIVE_TEST_FIXTURE_DIR`. `cargo run --example remaining_macos_evidence` binds own sources separately from the original baseline, inherited platform-search slice and root's pure window-placement module, and collects actual screen/AX copy and PNG hashes. Physical focus, personal indexes/processes/windows, real screen lock/kill and unlocked-Mac acceptance are excluded. This candidate does not authorize an incomplete app installation.

Issue [86](https://github.com/viggomeesters/ruycast/issues/86) implements the maintainer's 30 October 2026 decision to move the complete Ruycast product into Rust. It supersedes the older hybrid language target. AppKit remains the native UI API, called directly through objc2; no Swift helper or server is used by this crate.

Production entry planning accepts no arguments or `--native`, and `--headless`, with `RUYCAST_HOME` / `RUSTCAST_HOME` overrides or the default `~/.config/ruycast`; configuration aliases and the existing selector still apply. Hidden and test probes require an explicit profile and retain their owned-fixture checks. `--version` is independent of profile and native services. Status reports nonprompting accessibility/input-monitoring booleans and known functional health; `productionReady: false` remains a separate acceptance gate. This wiring is tested through pure launch plans and owned headless processes; normal personal-profile AppKit startup has not been executed in this slice.

**Incomplete development host. Do not install as Ruycast.** The current slice owns a command catalog, bounded navigation, query results and activation intent in Rust, plus an AppKit panel/text field/delegate and a native scrollable results table. The normal check uses synthetic commands; an explicit-profile hidden check reads the migrated HostState and ranking without executing actions. A separate headless entry exposes the migrated control/model contracts described below. The connected development runtime now includes Actions and direct alias/hotkey forms; complete execution, visual details and other existing features remain to migrate. A fixture-only executable is not comparable to full app functionality or size.

rust-native/target/release/ruycast-native --check-native /absolute/output.png dark 760

The native check runs on the main thread with activation prohibited and the panel never shown. It verifies the actual NSTextField delegate, native marked-text Return suppression, exact alias resolution and Return intent, the search accessibility name, and quarantine after a deliberately injected callback panic. The expected panic hook writes an isolated test message to stderr; the panic is caught before crossing the Objective-C callback boundary. Failed owners cannot be reused. A cleanup guard disconnects the weak delegate and closes the panel on all returns. No external key events, browser discovery, clipboard access or action execution occur.

`--benchmark-model` uses synthetic 500/1000/5000/10000 catalogs and 1000 timed queries per size after ten warm-ups. It measures only the new session and existing Rust search kernel. It omits current-app recency preparation, analytics, main search aggregation, UI/presentation and many features. Do not interpret comparison with the complete Swift-host benchmark as a causal rewrite gain.

The frozen 0.8.25/build65 remains historical measurement evidence. Preserve the current working installation (the separate native-edit repair delivered 0.8.26/build66) until complete behavior/configuration/CLI/security parity and independent delivery review. The public migration issue and its linked issues track the remaining technical acceptance. No GitHub Actions.

## Rust foundation

The library now owns an enabled catalog, typed in-process ranked search, stable empty-query usage ordering, bounded successful-choice persistence, configuration last-good reload, profile/config-directory selection and initialization, and locked save/relocation using the same private writer source as the existing CLI. The new `HostState` composes configuration, ranking and session without starting native effects. Ranking/config refreshes preserve selected identity or clear a removed target; they never substitute another command for a removed selection.

The writer reports whether rename already published the payload before a directory durability failure. The host reconciles that outcome and rechecks mapping/target instead of claiming the old bytes are still on disk. Relocation retains the original and removes only its own unchanged failed copy; post-publication external edits remain available for recovery. These checks cover cooperating writers and detected races; they are not atomic CAS guarantees against a malicious process running as the same user.

## Shared script primitive

The existing CLI `__run-script` and the Rust core now use `rustcast_core::script::run`. It executes an explicit executable with literal arguments, null stdin, separate bounded stdout/stderr retention (65,536 raw bytes each), optional absolute request deadline and cooperative cancellation. It continues draining excess output with a per-poll budget. Cancellation/deadline results are unknown-effect outcomes; never automatically retry. The first observed completion/interruption reason is retained during cleanup. UTF-8 replacement can expand the final encoded text beyond the raw retention cap.

A process-group guard is established immediately after spawn. The leader remains waitable through `waitid(WNOWAIT)` until all TERM/KILL signals are finished; exactly one final wait reaps it. Every error/panic after spawn attempts group cleanup and leader reap. On Darwin, signalling a zombie-only group returns EPERM: normalization requires the still-unreaped leader to be exited and a complete bounded group inventory with no live members. Truncation, inaccessible live processes and inspection errors remain failures. A no-op async-signal-safe `pre_exec` uses Rust 1.92's fork/exec error-pipe path, which reaps a failed exec before returning the launch error; repeated missing-executable fixtures protect that ownership behavior.

Cleanup covers the owned process group, not descendants that deliberately leave it. Polling/output work and TERM grace are bounded; the final OS wait is not a hard real-time guarantee. No independent SIGCHLD handler may reap these children. This synchronous primitive belongs on a bounded execution worker. The ordinary-script admission, completion, cancellation, input substitution and initial metadata/usage integration now use the executor below; complete result handlers and richer diagnostics/analytics remain pending. Ordinary saved scripts now reach it through the development host’s bounded asynchronous execution authority described below. This does not constitute complete native execution parity.

`tests/script_basic_process.rs` and `tests/script_fault_process.rs` use actual disposable children and a mandatory-trace macOS interposer to test literal CLI/core response parity, independent streams, flood cancellation/timeouts, inherited pipes, TERM-resistant process groups, panic/error cleanup, repeated failed starts, descriptor/read/wait faults and fail-closed live EPERM/inventory failures. Traces require final reap after group signals and prohibit later signals to the reaped identity. The probe's waitpid(-1) is an assertion in its isolated process; production never uses it to collect unknown children.


## Bounded host execution

Saved ordinary scripts now use one execution authority for control/CLI execute, palette Return, row click and Actions Run. Literal whole-argument `{input}` and separately generated `{uuid}` values are prepared once; prompt validation and checked addressable-size arithmetic (metadata, vector overhead and expanded arguments) precede command cloning/thread admission. The socket packet quota does not limit saved command data or expanded arguments; actual spawn errors remain owned by the script runner. The separate development supervisor-header quota still needs baseline reconciliation. Disabled, stale or unsupported contracts do not launch. Dry-run remains side-effect free. Known capture/private-bridge/Apple Shortcuts contracts remain blocked until their specific handlers are ported. Ordinary script choices/detail envelopes are handled by the native result owner and controls below; invalid or uncertain completed presentation receives a check-before-retry notice and is never automatically rerun.

At most 16 workers exist; at most 15 originate in CLI requests, leaving one of the unchanged 16 transport clients for status/quit. Workers own no UI handles or mutable profile authority. Each has a pre-reserved result slot and cooperative cancellation; full notification queues cannot lose results. Results are harvested independently of thread exit, delivered once, and finished threads are joined separately. A full client disconnect cancels its job; a write-half close can still receive its result. Control 310-second and CLI 312-second deadlines remain; native five-second input deadlines govern admission, not the script’s own allowed runtime. User Escape/window close cancels native work, while queries suppress late effects without cancelling the script. Recorder/editor/menu and marked-text arbitration retain priority. Native Escape allows the Function flag and preserves active composition.

Main-thread query/action intent counters, per-window execution serials and query/catalog/dismissal/selection/editor/menu checks prevent a completion from hiding newer work. The main view also rejects a completion published after a newer local intent, and the owner restores its prior visibility before processing that intent. A running label is derived from actual active work; it cannot remain after an invalid/replaced configuration suppresses the result. Actual configuration storage is reconciled before usage/ranking attribution. A replacement receives no old command’s counts. Jobs are cancelled/joined and completed responses/logs accounted for before releasing the socket/profile lease; pending wire acknowledgements share one three-second shutdown budget. OS child cleanup remains subject to the primitive’s documented final-wait limitation.

The owner maintains compatible usage counts and launcher-only recency plus schema 1 operational start/finish metadata. Logs are owner-private, limited to 500 entries/seven days and a byte budget; typed loading discards unknown fields, rejects wrong optional/detail types and prunes immediately. Existing invalid logs remain untouched until confirmed clear. Values, credentials, URLs and home paths are redacted from logged command identifiers; arguments, stdout/stderr, raw errors and provider diagnostics are not stored by this initial metadata journal. A successful effect with failed usage persistence reports `actionCompleted` and is never rerun. Logging errors remain queryable. Writes currently run on the serialized owner: this slice establishes no absolute storage-I/O latency bound; batching/service isolation and richer existing diagnostic/aggregate-analytics parity remain open.

`tests/execution_process.py` runs real disposable headless and hidden AppKit hosts through the unchanged CLI and real sockets.
