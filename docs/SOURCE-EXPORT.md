# Rust source export

Build the source tool with `cargo build --locked --manifest-path rust-native/Cargo.toml --bin ruycast-source`. This requires Rust and the macOS SDK, not a Swift compiler or Swift host. The unchanged system `/usr/bin/gzip` compresses/decompresses the Rust-generated canonical USTAR stream with no timestamp or filename metadata.

Run `cargo run --locked --offline --manifest-path rust-native/Cargo.toml --bin ruycast-source -- export --repo /absolute/source --out /absolute/staging/new-name`. The tool creates a clean directory, sibling `.tar.gz` and `.tar.gz.sha256`, without replacing existing paths. Missing staging parents are created through no-follow directory descriptors. `cargo run --locked --offline --manifest-path rust-native/Cargo.toml --bin ruycast-source -- verify --source /absolute/staging/new-name` verifies a clean export without Git or `.go`. Add `--repo /absolute/source` to also compare it with the trusted original source. Keep Cargo build output outside a clean export (for example with an explicit external `CARGO_TARGET_DIR`). `list --repo` returns the exact selected paths.

`PUBLIC-SOURCE.json` schema `ruycast.public-source.v2` records sorted SHA256 files, normalized POSIX modes, roles and the compiled Rust product version. The same names, bytes and modes produce the same USTAR and gzip bytes for a given gzip toolchain. The version, public default configuration, source-tool implementation and allowlist must exactly match the bytes compiled into the tool; rebuild after changing them. The receipt contains no absolute source paths, user IDs, timestamps or private workflow state. It is an integrity receipt, not a signature or publication proof; use the independently trusted release checksum for authenticity.

The explicit allowlist is `rust-native/src/bin/ruycast-source/policy.rs`. New product/test files must be reviewed and added explicitly. Unreviewed paths inside the Rust product-source trees are refused rather than silently omitted. Unknown other files, examples/staging merge helpers, `.go`, profiles, private adapters, signing keys, build output and GitHub Actions are never auto-discovered or copied. Source reads anchor each component to no-follow directory descriptors and reject links, hardlinks, special files, oversized files and signing/key material. Source identities/bytes are rechecked after staging. Concurrent mutation detected during copying refuses the export; this is not a filesystem snapshot against a malicious same-user writer after the final check.

`bench/reference/0.8.26/` is omitted from source exports and removed from the checkout; its original bytes remain recoverable through Git history. `Package.swift` and `Sources/` remain exported because current validation and source-policy callers still require those migration references. The no-op `Tests/LauncherCoreTests/CoreTests.swift` runner and target are retired; historical test mappings remain in Rust provenance. This export change does not claim that the checkout is already 100% Rust, and exporting a candidate does not publish a release or install anything.

The retired `Sources/RuycastApp/SystemChecks.swift` helper is absent from both the export allowlist and Swift reference lock. Its `--check-system` route and nested Feedback call/result flag are removed; `SystemServices.swift` remains an exported product reference. The Rust oracle inventory retains the original helper SHA256 `c70cc5149a16a43102cc8a853bfb5a38bc6a9b3b542b4f6b7388339f1737ffa4` and nineteen assertion mappings as historical provenance. Rust uses a fresh opaque menu token per scan and runtime-owner adoption after a worker wake; the old stable-token and literal AppKit-main-thread callback assertions are not claimed as exact Rust contracts. Feedback and caller source pins reflect the changed files. `productionAccepted=false` remains unchanged.
